read_or_write_parquet <- function(con, table_name, file_name) {
  if (!file.exists(file_name)) {
    table <- dbGetQuery(
      con,
      glue::glue("SELECT * FROM {table_name};")
    )
    nanoparquet::write_parquet(
      table,
      file_name
    )
  } else {
    table <- nanoparquet::read_parquet(
      file_name
    )
  }
  table
}

In practical terms, all samples are listed either as Fresh water or Salt water… which is a problem, because these two don’t exist in the lookup table environ_compartment. This shouldn’t be difficult to fix, since we can just add/rename columns?

In eData, we have a compartments table that consists of ENVIRON_COMPARTMENT (which maps mostly) to RADB.environmental_con, and ENVIRON_COMPARTMENT_SUB, which is mostly comprehensive.

The environmental compartment fields are important for organsing and understanding environmental data, so I think they should be given high priority. Some technical/harmonisation work is needed, but I don’t see it being especially complicated.
