1.1 foreign key environmental_con.measured_reference_id == user_ref.reference_id

  • As we’re only interested in eData and not qData, we want to know if all eData entries correspond to a single reference
  • measured_reference_id is stored as a character and reference_id as a double, which may cause issues with joining tables
  • Drilling deeper into the data several issues are apparent: many entries in environmental_con have no measured_reference_id, and some measured_reference_id are not integers

  • eData generates a compact text reference ID based on the reference date, the first author’s last name, and the first three words of the title (e.g. 2018Last1AStudyOf)

  • This is unlikely but technically might to generate non-unique IDs (i.e. if two papers are published the same year with the same first three title words and first author last name)

  • This also has the benefit of being far more more human-friendly than an integer code

ImportantRecommendations
  • Review use of reference ID in existing data
  • Harmonise across eData/qData/RADB

6 reference_type

Code

  kable_abbreviate(n = 20)
reference_type n
PRIMARY 598
REVIEW 101
  • reference_type is always either PRIMARY or REVIEW
  • Edge cases may exist (e.g. databases), but aren’t anticipated to be a real issue
  • No controlled vocabulary constraint appears to exist for this variable at this time
  • eData’s References - REFERENCE_TYPE variable tracks whether the reference is a book/article/etc, akin to bibtex’s entry type
  • this is used to make various data specific to certain references conditionally mandatory (e.g. books and reports need a publisher, etc.)
ImportantRecommendations
  • Rename eData REFERENCE_TYPE to ENTRY_TYPE for consistency with bibtex
  • Extend reference_type to include Other category, add controlled vocabulary
  • Harmonise across both

Assessment

  • Priority: 1/5
  • Difficulty: 3/5
